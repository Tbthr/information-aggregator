• 编程 agent 和工具：

  - @chadfowler 转发 aicoding.leaflet.pub，并引用 @arni0x9053 对近未来的设想：不再要 CI，agent 写代码时就按规则证明每次改动；代码只是缓存，规则留下、代码用更好的模型重新生成；不要 staging，用仿真代替；人用自然语言指挥、agent 来「编译」。再往下引的是 @thorstenball：为什么还在用分支？从第一性原理看 PR 已经说不通，只用来触发 CI 的 PR 其实就是一个大提交（后文被截断）。

  - @maestro4020 列了 Codex SDK 三个待改进点：rollout 要求 json 文件里必须有顺序编号；派生出来的 codex 进程不暴露自己的 pid，中止一轮时杀不掉它启动的 MCP server；基于内容的缓存（后文被截断）。发帖账号很小，属于个人使用反馈。

  - @phodal（关注抽样）回答 Coding、Cowork、Science 适不适合放进同一个桌面应用：主要看需要哪些强领域能力，比如 Codex 做了大量 Office 三件套的定制，但写代码也要写 pptx 所以不明显；如果是面向某些领域的 Science，就会有很多类似 Office 的工具，放一起问题不大，只是要设计得更可定制。

  - 观点两条：@codeviking 说大家都在谈用 agent 写代码，但 agent 正在变成代码的一部分，会像数据库一样普及（后文被截断）；@joshuagunnn 说未来几年最大的 alpha 是重新找出软件史上被忽视的想法，看它们当年失败是因为太需要人工维护，还是算力太少。
